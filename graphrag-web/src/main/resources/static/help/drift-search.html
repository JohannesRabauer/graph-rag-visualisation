Drift Search

Start with communities for context, spawn a sub-question for the best ones, answer each locally, then synthesise. Broad first, precise second.

Overview

The drift tree on the canvas draws the branches.

The idea

Canonical DRIFT search (Dynamic Reasoning and Inference with Flexible Traversal) primes the search with community information, lets the model generate follow-up questions, and refines them with local searches, combining global context with local precision.

In this demo

AnswerDriftSearch emits a COMMUNITY step for every community, then keeps the ones tied for the best keyword score as candidates. For each candidate it asks LlmPort for a sub-question; the default implementation, which is also what the real OpenAI adapter uses, just glues the question and the community summary into a template. Each sub-question runs a full AnswerLocalSearch and its steps join the trace. The synthesis step reuses the first branch that found a relationship hop, or says no grounded match was found.

If no community scores above zero, there is no viable sub-question and the answer says so.

With a real embedding model configured (OPENAI_API_KEY set), the candidates are instead the three communities whose summaries are closest in meaning to the question, in similarity order, and the sub-question local searches seed by meaning too; a corpus without community embeddings, or the offline stub, falls back to the keyword candidates above.

With a real LLM configured (OPENAI_API_KEY set), at most the first three candidates spawn a branch, and the branches gather context instead of answering: under its SUB_QUESTION_SPAWNED step, each sub-question collects the same bounded context a Local Search would (seed entities, up to 10 relationships, up to 5 source passages as TEXT_UNIT steps), with no model call of its own. After the last branch, one model call writes the answer from the candidate community summaries plus everything the branches found, each item listed once even when several branches reached it. That answer is the single SYNTHESIS step at the end of the trace, and its [n] citations name source passages that are steps of the same trace, listed in the response's citations. If no branch found anything, the answer says no grounded match was found, without a model call. If the model says the context does not answer the question, you get a plain "no answer" with the reason; if the call fails, you see an error.

Simplifications

  • Offline (no key), no mode is LLM based: no source passages are read, Global quotes one summary, and the Local answer and the Drift synthesis are deterministic templates.
  • With a key, the context is a fixed-size slice rather than canonical GraphRAG's token-budgeted mix, and citation markers are shown as plain text.
  • Drift sub-questions are deterministic templates, not model output, with or without a key.
  • When an OPENAI_API_KEY is set, entity extraction, community summaries and the Local, Global and Drift answers are LLM-generated, and entity and community embeddings pick the search starting points by meaning. Without a key (offline), regex extraction and hashed bag-of-words embeddings stand in, and starting points are matched by keywords only.

Sub-questions are template text, and offline so is the synthesis, so Drift is less "reasoning" here than the name suggests.
