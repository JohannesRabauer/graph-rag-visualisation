Looking inside

Vector search versus GraphRAG

The Compare button re-runs your question through plain vector similarity search, with no graph at all, so you can see how the two approaches differ.

Overview

The result opens in the Vector Space tab.

The idea

Baseline RAG retrieves the chunks most similar to the question and lets an LLM answer from them. GraphRAG argues that adding structure helps with questions that span documents or need a whole-corpus view, where similarity alone finds only local passages.

In this demo

AnswerVectorBaseline embeds the question, computes cosine similarity against every stored chunk, keeps the top five, and builds the answer through LlmPort (by default it just joins the chunk texts). Its trace has a query-embedded step, one step per chunk with its score=, and a synthesis step. It is only reachable from the Compare button, never from the mode radios. After it runs, a side-by-side panel under your graph answer shows both answers and what each approach touched (communities, entities and hops on the graph side; ranked chunks and best score on the vector side), and a link jumps to the Vector Space tab.

The graph modes are keyword based here, so this is not a quality contest: the comparison shows two mechanisms. See the modes.

Simplifications

  • With no API key the embeddings are hashed word counts, so the "vector" side is really word-overlap too.
  • No live layer for this comparison in the help pane.
