Looking inside

Vector search versus GraphRAG

The Compare button answers your question twice, fresh: once with the answer's GraphRAG mode and once with plain vector similarity search, with no graph at all. The Compare tab shows both answers side by side, with their sources, key figures and a short verdict on where they differ and why.

Overview

The result opens in the Compare tab; the Vector Space tab shows where the vector side's chunks sit.

The idea

Baseline RAG retrieves the chunks most similar to the question and lets an LLM answer from them. GraphRAG argues that adding structure helps with questions that span documents or need a whole-corpus view, where similarity alone finds only local passages.

In this demo

AnswerVectorBaseline embeds the question, computes cosine similarity against every stored chunk and keeps the top five. With an OpenAI key it hands those five chunks to the same answer prompt the GraphRAG modes use, each as a numbered "Source passage", so the vector answer is LLM-written and cites its chunks as [n] exactly like a graph answer (CitationResolver resolves both). Without a key it just joins the chunk texts and cites nothing. Its trace has a query-embedded step, one step per chunk with its score=, and a synthesis step. It is only reachable from the Compare button, never from the mode radios.

The Compare tab

Pressing Compare sends one POST /api/corpora/{corpusId}/compare. CompareAnswers runs the graph mode and the vector baseline one after the other, times each, and returns both answers with their citations and traces. Nothing is added to the chat: the button turns into a "Comparison ready" link, and the Compare tab opens. Clicking the link later reopens that answer's comparison. A note under the question says both sides were answered fresh for this comparison, and "Run again" repeats it for the same question and mode (a new LLM call per side, so a live answer can change).

  • Two columns. GraphRAG on the left, Vector Search on the right, each with its [n] markers and a Sources list. A graph source opens its text unit; a vector source opens its chunk (GET /api/corpora/{corpusId}/chunks/{chunkId}). A source marked "also used by the other side" was retrieved by both: the vector chunk's text sits inside a passage the graph side read, from the same document.
  • Retrieved passages. Under each answer, every passage that side retrieved, cited or not: the text units the graph side read, and the five chunks vector search kept. Each row opens its full text and carries the same "also used by the other side" badge. Without an OpenAI key the graph side matches keywords and reads no passages, so its list says so.
  • Key figures. Per side: how many context items it retrieved (entities, relationships, communities and passages for GraphRAG; chunks for Vector Search), from how many distinct documents, how many citations its answer makes, and how long it took.
  • Verdict. One or two sentences naming the concrete difference and its reason. With an OpenAI key it is written by the model from the two answers and the measured figures ("LLM verdict"); otherwise, or if that call fails, it is a fixed rule over the figures ("Rule-based summary") that says which side retrieved more and how many passages overlap, without judging correctness.
  • Replay. "Replay GraphRAG" and "Replay Vector" start the usual trace replay on the Knowledge Graph and Vector Space tabs.

The graph modes match by keyword without a key, so this is not a quality contest: the comparison shows two mechanisms. See the modes.

Simplifications

  • With no API key the embeddings are hashed word counts, so the "vector" side is really word-overlap too.
  • No live layer for this comparison in the help pane.
  • Both replays run one after the other, not side by side.
  • Token usage per side is not shown.
