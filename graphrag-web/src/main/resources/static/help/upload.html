Getting started

Uploading a corpus

Give the app your own documents (.txt or .pdf). It reads them, builds a knowledge graph from them, and then lets you question that graph.

Overview

The progress banner shows the build as it happens.

The idea

GraphRAG starts by turning unstructured text into a structure: an LLM reads the documents and extracts entities (people, places, things) and the relationships between them. That graph, not the raw text, is what later searches walk.

In this demo

Each file name is checked against the registered parsers by IngestCorpus: PlainTextDocumentParserAdapter for .txt and PdfDocumentParserAdapter for .pdf. The first unsupported file aborts the upload, and an unreadable file is reported as such. A successful upload gets a fresh corpus id and starts building immediately; the page then follows the build over a progress stream.

Extraction is done by ExtractEntitiesAndRelationships through LlmPort. With an OPENAI_API_KEY a real model extracts; without one a deterministic regex-based stub does, so the graph is cruder.

Simplifications

  • Extraction quality depends on the model. The stub finds far fewer entities than a real LLM.
  • Only one corpus is active at a time; loading another replaces the current view (earlier ones stay in the history list).
