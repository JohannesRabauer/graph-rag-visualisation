Search mode

Global Search

Read every community summary, pick the one that overlaps your question most, and answer from it. Built for broad questions like "what is this corpus about?".

Overview

Each community is one trace step, so the trace lists all communities, not only the winner.

The idea

In canonical GraphRAG, global search maps the question over community reports (LLM-written summaries of graph clusters), asks the model for partial answers, and reduces them into one answer. That lets it answer questions no single entity or chunk contains.

In this demo

AnswerGlobalSearch reads only the communities already persisted by DetectCommunities; it never triggers detection itself. It scores each community summary with KeywordMatcher and the best score wins (ties go to the smaller community id). The answer is "Across the corpus, the strongest signal is that" followed by that summary. If no summary matches, it says so honestly. If the corpus has no communities, because detection is still running or because no group of related entities reached three members, it returns a no-answer with a reason.

With keyword matching (offline), the trace is one COMMUNITY step per community, in read order. The score is not recorded, which is why the live view below marks the winner by finding its summary in the answer text.

With a real embedding model configured (OPENAI_API_KEY set), Global Search instead records only the three communities whose summaries are closest in meaning to the question, in similarity order, and answers from the first; a corpus without community embeddings, or the offline stub, falls back to the keyword scoring above.

With a real LLM configured (OPENAI_API_KEY set), Global Search is map-reduce, as in canonical GraphRAG. Map: it reads up to 30 communities (closest in meaning first, otherwise by keyword score), five per model call, and records each as a COMMUNITY step; for each one the model writes up to three key points that help answer the question, scored from 0 to 100. Reduce: points scored 0 are dropped and the 20 best are kept, then up to two source passages are added, as TEXT_UNIT steps, for each of the first five communities those points come from. Passages are ranked by the weight of the relationships inside the community that cite them, plus one per member entity citing them, and a passage already read is not repeated. One more model call writes the answer from the points and the passages. If no point scores above 0, you get a plain "no answer" without that last call. The model sees every item numbered and must cite passages inline as [n]; CitationResolver keeps only citations of passages, renumbers them from 1 and lists them in the response's citations, so each [n] names a passage that is also a step of the same trace. If the model says the context does not answer the question, you get a plain "no answer" with the reason. If the model call fails, you see an error; nothing is retried.

Simplifications

  • Offline (no key), no mode is LLM based: no source passages are read, Global quotes one summary, and the Local answer and the Drift synthesis are deterministic templates.
  • With a key, the map step reads at most 30 communities and the reduce step a fixed number of points and passages rather than canonical GraphRAG's token budgets, the map calls run one after another, and citation markers are shown as plain text.
  • Drift sub-questions are deterministic templates, not model output, with or without a key.
  • When an OPENAI_API_KEY is set, entity extraction, community summaries and the Local, Global and Drift answers are LLM-generated, and entity and community embeddings pick the search starting points by meaning. Without a key (offline), regex extraction and hashed bag-of-words embeddings stand in, and starting points are matched by keywords only.

Offline there is no map or reduce phase: exactly one summary is quoted. The live view below marks the community whose summary the answer quotes; with a key it marks the first community read, which is not necessarily the one the answer relies on most.
