Looking inside

Vector Space

A 2D map of the corpus text chunks. Chunks that use similar words sit near each other. After a vector comparison, your question lands on the map too.

Overview

The tab appears once you press "Compare with Vector Search" under an answer. That opens the Compare tab, with the cited vector answer next to the graph answer and a verdict; this tab shows the vector answer's text and the map.

The idea

A vector index turns each text chunk into a list of numbers (an embedding) so similar meaning gives similar numbers. Plotting those in 2D gives a feel for how the corpus clusters in embedding space.

In this demo

ConstructVectorIndex splits documents into chunks of about 500 characters, embeds each one and stores it. TwoDProjection fits a simple PCA to two dimensions over the corpus embeddings and saves the fitted model, so a later question can be placed into the same map without moving any chunk. With no API key the embeddings are 64-number hashed bag-of-words vectors, which capture word overlap, not meaning.

"Replay Vector" in the Compare tab switches here and lands the question on the map, step by step, lighting up the five chunks it retrieved: the same chunks the vector answer cites as its sources.

This view is generic only: there is no per-answer live layer for it.

Simplifications

  • A 2D projection throws away most of the information; nearby dots are only a hint of similarity.
