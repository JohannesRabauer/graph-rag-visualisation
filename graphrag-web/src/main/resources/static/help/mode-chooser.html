Search modes

Choosing a search mode

Three ways to ask the same question of the same knowledge graph. They differ in where they start looking and how much of the graph they read.

Overview

  • Local: precise, about a named thing.
  • Global: broad, about the whole corpus.
  • Drift: broad first, then precise.

Read one in depth: Local Search, Global Search, Drift Search.

The idea

Canonical GraphRAG offers several query strategies over an entity graph. Local search answers questions about specific entities by pulling in their neighbourhood. Global search answers corpus-wide questions from summaries of communities. Drift combines them: it starts from community-level context and drifts into local detail. The mode is a per-question choice, so the same chat can mix them.

In this demo

The radio buttons above the question box set the mode for the next question only. Each answer is tagged with the mode that produced it. The classes behind the modes are AnswerLocalSearch AnswerGlobalSearch AnswerDriftSearch. A fourth path, AnswerVectorBaseline, is not a radio option: it runs from the Compare button on an answer (see vector search versus GraphRAG).

All three graph modes are keyword based and deterministic: they score text with KeywordMatcher and never call an embedding model.

Simplifications

  • Local Search here is not chunk based and not LLM based: no text chunks are retrieved and no model writes the answer.
  • Drift sub-questions and the synthesis are deterministic templates, not model output.
  • When an OPENAI_API_KEY is set, entity extraction and community summaries are the only LLM-generated parts. Without a key, regex extraction and hashed bag-of-words embeddings stand in.
