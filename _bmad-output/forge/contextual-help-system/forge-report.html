Contextual Help System for GraphRAG Lens

Forge session, 2026-09-30 · Root · goal: make the idea better · existing project

Outcome

Every meaningful control or area of the UI gets a "?" that opens a docked help pane. The pane teaches a concept and shows, for the search modes, what actually happened in the user's own data. It works for one person who is both the reader and the live presenter, and it stays honest about what Lens simplifies compared with textbook GraphRAG.

Locked decisions

  • Pane: docked, non-modal, stays open. Another "?" swaps the content. Esc or close dismisses it. It becomes an overlay on narrow widths, and type is projector-legible.
  • Two layers per topic: a generic layer (header, abstract, overview, hand-drawn SVG) and a live "in your data" layer from the last answer's retrieval trace. The live layer has an empty state and follows new answers.
  • Honest content: "The idea" (canonical GraphRAG), "In this demo" (what Lens really does) and a simplifications callout.
  • Live layer in v1: Local, Global and Drift only. Everything else is generic.
  • Storage: one HTML file per topic in static/help/ plus a data-help registry and one small vanilla-JS module.
  • Drift guards: a test that every "?" maps to a topic and back, and a test that classes named in "In this demo" still exist.
  • 17 topics, with Local, Global and Drift as separate articles plus a comparison guide.
  • Three phases: pane, registry, guards and the search-mode articles first; then graph and looking-inside topics; then data-in topics.

Rejected, and why

  • Generic-only diagrams: they never show real results.
  • Live-only diagrams: they are empty before the first question, and static examples would show Holmes on other datasets.
  • Canonical-only content: the code disagrees with it. Local Search is one keyword-matched seed and one hop.
  • Modal or auto-closing pane: the audience loses sight of the graph.
  • Generated diagrams and a content system: high cost for little value.

Weak points that survived

  • It is unknown whether the offline demo's pre-recorded answers carry a retrieval trace. If not, the live layer is empty there.
  • The class-existence guard cannot prove the prose is still true. Renames get caught, but silent behaviour changes do not.
  • Global Search's trace holds only community steps, so its live layer is thin.
  • Seventeen long articles are real writing and review work, and accuracy review sits with Root.

Also done

Fixed the search-mode bug: a browser-restored radio left the JS mode stuck on Local. The fix is syncModeFromDom() in upload.js, with regression test RestoredSearchModeUiTest, which fails without the fix and passes with it.
