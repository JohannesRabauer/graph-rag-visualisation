topic: Java web app to visualize GraphRAG with Neo4j
updated: 2026-09-19T07:29

- (decision) Primary purpose: educational/demo tool to visualize how GraphRAG works, not a production product
- (decision) Secondary ambition: could seed a reusable Java GraphRAG library, since user perceives a gap in Java GraphRAG libraries/demos
- (decision) Audience: solo builder initially, intended to be shown on live coding streams
- (decision) Stakes: passion project, low formal rigor needed, but built with an eye toward eventual open-source publication
- (decision) Tech constraints: Java-first, Neo4j as the initial/optimized graph DB, other DBs possible later (not required for v1)
- (assumption) No existing source material provided by user; brief will rely on facilitator research into current GraphRAG landscape
- (event) Research: confirmed real gap in Java-native GraphRAG tooling (Neo4j's neo4j-graphrag SDK is Python-only; LangChain4j graph patterns still immature); supports the library stretch goal
- (event) Research: no known tool visualizes live GraphRAG retrieval mechanics (community traversal, local vs global search) on Neo4j -- closest analogs are post-hoc artifact viewers (graphrag-visualizer) or vector-RAG-only pipeline explainers (RAG Playground, RAGViz); genuine differentiation space identified
- (decision) v1 scope: architected with future OSS library extraction in mind from day one, not a throwaway demo hack
- (decision) Retrieval must use live LLM calls at demo time -- explicitly non-deterministic, not a canned/fixed-output demo
- (decision) Build shape: single polished result (not built incrementally episode-by-episode), but must showcase multiple GraphRAG methods/techniques side by side rather than just one retrieval path
- (decision) Working mode: coaching path selected
- (decision) Corpus: public-domain fiction (e.g. Sherlock Holmes stories) confirmed for v1 demo
- (decision) Methods to showcase: local vs global search (Microsoft GraphRAG split) confirmed, PLUS the community-building/detection step itself (e.g. Leiden clustering into hierarchical communities) as a visualized method, not just the two search modes
- (decision) No fallback/cached safety net for live demo -- live LLM failures during streaming are an accepted risk, by design
- (decision) Success criteria (primary): personal mastery -- being able to explain GraphRAG live and correctly, confidently
- (decision) Out of scope for v1: arbitrary user-uploaded corpora (fixed Sherlock Holmes corpus only); also confirmed Neo4j-only (no multi-DB abstraction yet), single-user/local run (no auth/hosting), no formal retrieval-quality benchmarking dashboard -- all deferred to future
- (decision) LLM provider: OpenAI for v1, but must be easily swappable -- use LangChain4j as the abstraction layer specifically to keep provider choice open
- (decision) UX direction (light, full pass deferred to bmad-ux): modern, minimalistic, easy to understand visually; runs in the browser with minimal setup/installation friction
- (event) Discovery complete; drafting brief.md and addendum.md for user review
- (event) User approved draft; polish pass (structure/prose) applied to brief.md and addendum.md; status set to final
- (override) Reverses prior scope decision: v1 now supports ingesting arbitrary user-provided files (plain text and PDF), not just the fixed Sherlock Holmes corpus. Sherlock Holmes is retained as the built-in demo/test dataset. Reason: surfaced while narrating the core user journey during PRD discovery -- the 'throw files in' step was meant literally as a real feature, not just describing the fixed ingestion step.
