- (decision) Visual/interaction philosophy: the graph/retrieval visualization is the hero -- UI chrome should recede, not compete for attention. No strong personal style reference; user delegated aesthetic exploration but wants concrete options to react to, not a blank check.
- (decision) Core value prop for UX: ease-of-use is NOT the differentiator to optimize for showmanship -- the app should be a 'no-brainer to use' precisely so attention stays on teaching GraphRAG mechanics, not on learning the app itself. Tutorial-like clarity, easy to read and understand, is the primary design goal.
- (decision) Community detection visualization is a toggle (default OFF), not an always-on step. Detection itself still runs in the background regardless of toggle state -- the toggle only controls whether its formation is shown/animated. Lets the user demonstrate 'with vs without' the community view for teaching. Implies a single continuous screen (not a gated step sequence): chat/graph is available while ingestion+detection run in parallel.
- (decision) Visual direction chosen: 'Instrument' -- scientific data-viz/lab-instrument register, light mode, bright white canvas, hairline chrome, one calm blue accent, monospace reserved for data/step labels, precise ticked scrubber
- (decision) No separate start/setup screen -- empty state lives on the main page
- (decision) NEW SURFACE for v1: a separate 'Explore the Graph' page for free exploration (pan/zoom/click the full knowledge graph and its communities, independent of any query) -- not in the original PRD feature set. Will need reconciliation into the PRD (new feature + FRs) during UX finalize input-reconciliation step.
- (decision) Explore page: click a node to see its connections, details, and tags. Communities are also visualized on this page (grouped/colored clusters), not just individual nodes.
- (decision) Communities are always visible on the Explore page (no toggle there, unlike the main screen where it's off by default)
- (decision) UJ-3 (Freely exploring the knowledge graph) confirmed as drafted
- (decision) Colorblind-safe community palette is a soft goal, best-effort -- not a hard blocker/requirement
