- (decision) [ADOPTED] Working mode: Fast path -- draft full spine with [ASSUMPTION] tags, user reviews once. Spine is the sole deliverable, no discussion doc/deck needed.
- (constraint) [ADOPTED from brief] Java-first implementation; Neo4j is the only graph store for v1; LangChain4j is the LLM orchestration layer specifically chosen to keep the LLM provider swappable; OpenAI is the initial provider.
- (constraint) [ADOPTED from brief addendum Notes for Architecture] File ingestion (text/PDF) needs a real parsing/extraction boundary isolated behind an interface, not a hardcoded loader. Provider abstraction must be an explicit architectural boundary. The 'library-in-mind' ambition means module boundaries should separate core GraphRAG/graph logic from the demo web app -- but no v1 feature should exist purely to serve that future-library goal.
- (constraint) [ADOPTED from PRD] Single-user, local-only, no auth/hosting/multi-tenancy. Docker Compose provisions Neo4j; OpenAI API key via env var only, no in-app config UI. No automatic retry/fallback for LLM failures -- errors must surface visibly, never crash/hang silently. Retrieval Trace is captured then replayed (not live-streamed).
- (constraint) [ADOPTED from PRD] 7 features / FR-1..FR-17: Document Ingestion (text/PDF/demo dataset), Knowledge Graph Construction (live LLM extraction into Neo4j), Community Detection & Visualization (Leiden clustering, toggle defaults ON first run), Query Interface (explicit Local/Global Search toggle), Retrieval Trace & Playback (captured, scrubbable replay), Setup & Deployment (Docker Compose + env var key), Graph Exploration (new: free-form pan/zoom/click explore page, always-on community view, node detail w/ connections+tags, read-only).
- (constraint) [ADOPTED from UX spines] Single-page main screen (chat + graph canvas + toggles + scrubber, no gated setup wizard) plus a second Explore page. Instrument visual direction: light-mode only, desktop/browser-only, no responsive/mobile requirement. No component library named in EXPERIENCE.md -- frontend framework choice is open.
